## 二、架构说明

### 2.1 整体架构

hr-boss-agent 采用"一个编排大脑 + 两个专业引擎"的架构：

```
┌─────────────────────────────────────────────────┐
│                  hr-boss-agent                   │
│              (model: qwen3.5-plus)               │
│                                                   │
│  ┌─────────────────────────────────────────────┐ │
│  │            hr-boss 编排技能                   │ │
│  │  意图路由 · 双路径调度 · 权威性仲裁 · 回答组装  │ │
│  └─────────────────────────────────────────────┘ │
│          │                        │               │
│          ▼                        ▼               │
│  ┌──────────────┐        ┌──────────────┐        │
│  │  Text2Cypher  │        │  GraphRAG QA  │        │
│  │     MCP       │        │     MCP       │        │
│  │  精确查账员    │        │  材料解读员    │        │
│  └──────┬───────┘        └──────┬───────┘        │
│         │                       │                 │
│         ▼                       ▼                 │
│  ┌──────────────┐        ┌──────────────┐        │
│  │ text2cypher-  │        │  GraphRAG     │        │
│  │ profile.md   │        │  固定数据集    │        │
│  │  业务口径     │        │               │        │
│  └──────────────┘        └──────────────┘        │
└─────────────────────────────────────────────────┘
```

**组件职责**：

| 组件 | 类型 | 职责 |
|------|------|------|
| `hr-boss` skill | 编排技能 | 意图路由、工具调度、权威性仲裁、面向领导的回答组装 |
| `text2cypher` MCP | 专业引擎 | 精确 HR 图谱查询：计数、平均、排名、名单、筛选、占比 |
| `hr-graphrag-qa` MCP | 专业引擎 | 语义分析与证据检索：员工画像、组织画像、趋势总结、风险发现 |
| `text2cypher-profile.md` | 业务口径 | Text2Cypher 单一口径来源，定义分组/排名/职称/组织/结果质量规则 |

### 2.2 权威性层级

```
Text2Cypher 精确数值（最高权威）
    │
    ├── 人数、平均值、名单、排名、占比
    ├── 筛选结果、聚合统计
    │
    ▼
GraphRAG 语义分析（补充解释）
    │
    ├── 背景原因、趋势解读
    ├── 证据归纳、结构分析
    │
    ▼
不可覆盖原则
    │
    └── GraphRAG 不得改写 Text2Cypher 的数值或名单
       GraphRAG 证据不足时宁可说明不足，不编造
       同一问题包含精确统计和背景解释时，先 Text2Cypher 后 GraphRAG
```

## 三、分题型评估

### 3.1 直接查询 (query) — 3 例

| 用例 | 问题 | Turn | 表现 |
|------|------|------|------|
| boss_e2e_001 | 研发那边现在有多少人？ | 1 | 未澄清口径，直接汇总 5 个研发部门给出 27 人，说明口径后建议可拆分查看 |
| boss_e2e_012 | 技术部的学历分布是什么样的？ | 2 | 正确识别多口径，列出 3 个技术部门让老板选，确认后给出分布表（本科 4/大专 1/大专以下 1，共 6 人） |
| boss_e2e_014 | 我们有多少个实习生？ | 2 | 未澄清口径，直接汇总所有实习生岗位给出 39 人，列出了覆盖的岗位类别 |

**变化**：001 和 014 从上一轮的"先澄清再查询"变为"直接汇总+说明口径"，效率提升但少了交互确认环节。012 保持了澄清模式。

## 五、综合评价

### 优势

- **递归错误清零**：低层 Text2Cypher 路径稳定性显著改善，复杂多跳查询不再耗尽递归配额
- **分析类回答质量高**：结论→依据→限制三段式结构一致，面向领导可读性好
- **人岗匹配实用价值**：跨结构化+语义的双路径协作在 8 道题型中展示了业务价值，跨子公司视野和方案选择模式是亮点
- **关键改进明显**：满意度、招聘进展、学历平均三个上轮的问题用例本轮得到修复
- **GraphRAG 使用克制**：agent 在数据不足时更多使用 Text2Cypher 先确认数据存在性，而非直接调用 GraphRAG 展开

### 待提升

| 问题 | 严重程度 | 涉及用例 | 说明 |
|------|---------|---------|------|
| **数据推测** | 严重 | 015, 040 | 查询为空时给"0 人"或自行推断降职原因，应改为"数据不足无法判断" |
| **澄清缺失** | 中等 | 007, 008, 011, 026, 027, 028, 034 | 高频模糊术语（高管/流动率/绩效排名）未建立必澄清机制 |
| **行为波动** | 中等 | 001, 014, 040 | 同一用例在不同轮次表现不一致（澄清↔不澄清，说不足↔推测） |
| **流动率口径** | 低 | 011, 034, 035 | 54.3% 使用全量历史数据，未默认使用最近 12 个月作为合理默认值 |

### 改进建议

4. **流动率默认时间窗口**：当用户未指定时间窗口时，默认使用"最近 12 个月"并注明口径，而非静默使用全量历史数据
